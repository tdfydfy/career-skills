# 首开价格报告

## 定位

把项目、市场、竞品、客户、房源、住宅与车位价格、经营影响组织成一份可复算、可审批、可执行的首开价格报告。沿用企业现行25页结构；用户提供新版模板时，以新版为准并保留本技能的校验规则。

本技能与 `launch-marketing-report` 分工：本技能回答“首开卖哪些房、按什么价格、预计卖多少、经营影响如何、需要批准什么”；完整营销总策划回答“如何定位、获客、传播、展示、组织销售并完成首开”。持销期局部调价路由到调价报告。

价格是项目营销策略的结果，不是独立起点。报告必须说明公司经营意图、市场容量与竞争、客户承价与客储、项目价值与货量如何共同推导首开范围、申请价格和销售目标。

## 必读资料

开始时读取：

- `references/input-checklist.md`：资料分级、字段状态和缺口处理。
- `references/slide-structure.md`：25页固定结构和逐页证据要求。
- `references/customer-rating.md`：A、B、C、D及B/C加减级口径。
- `references/quality-gates.md`：提交价格会前检查。

处理住宅定价时读取 `references/residential-pricing.md`；处理车位时读取 `references/parking-pricing.md`；出现利润率、净利润、IRR、回正或精装剔除时读取 `references/financial-calibration.md`。

在网络仓库内读取 `../framework/foundations/decision-reasoning-standard.md`，并按需读取 `../framework/contracts/` 的项目、市场、客户、库存、指标和财务契约，以及 `../framework/foundations/` 的客户、指标、财务和事实标准。先调用 `business-plan-marketing-strategy` 取得经营命题和策略约束，再调用价格货量能力形成价格方案。

## 工作流

### 1. 确认任务和基准版本

确认报告是新编、补全、更新还是审查；明确公司、项目、截止日、计划首开日、审批对象、首开范围和需要会议决定的事项。把拿地后的启动会作为项目整体策略和经营指标基准，把本次首开价格评审会作为首开范围、价格和量价目标的决策节点；记录两会间隔、经济技术指标和市场变化。原则上使首开及整盘指标保持或超越启动会，未达到时解释原因和修复路径。

### 2. 建立数据台账

按 `references/input-checklist.md` 建立字段台账。每个数字记录数值、单位、统计范围、截止日期、来源、版本、负责人和状态。状态只用：`已验证`、`待业务确认`、`待财务确认`、`假设`、`缺失`。

不要把“认筹客户数”“第一意向落位数”“去重客户数”混用；不要把建筑面积、可售面积和推售面积混用；不要把单价、总价、万元和亿元混用。

### 3. 形成市场与客户证据

完成政策边界、近一年供求量价、库存周期、在售/待售/二手竞品、重点竞品和分户型竞争结论。客户按 `references/customer-rating.md` 评级，分别统计户型、楼栋、意向价格、未转筹原因和待解决问题。

### 4. 建立价格推导链

先形成：

`公司经营意图与启动会基准 + 市场容量/竞品关系 + 客户承价/客储质量 + 项目价值/首开货量 → 首开范围、各业态价格、销售目标和整盘影响`。

逐项说明证据、经营含义、关键假设和失效条件。至少比较基准、保价或进取、去化或谨慎情景；不能只用单个竞品价格、目标均价或财务底价直接推出房号价格。

### 5. 制定住宅价格

按 `references/residential-pricing.md` 依次完成：首开范围与角色、首开均价及货值、楼栋/单元/楼层/户型价差、单价和总价离散度、剩余批次价格、整盘实现价及货值。每一级价差都要有价值因素或经营目的，不以凑均价替代价值排序。

### 6. 制定车位价格

按 `references/parking-pricing.md` 完成分类、数量、价格区间、去化目标、首批范围、客户意向、抗性、车住联动和敏感性。车位权属、销售条件、成本税费及利润公式未确认时，只输出经营情景，不输出已获财务认可的结论。

### 7. 测算并交叉核验

可运行：

```bash
python3 scripts/calculate_metrics.py input.json
```

用工具复算加权均价、货值、去化率、认筹目标与缺口、数量/面积占比、价格离散度和版本变化。脚本不计算企业专属利润、现金流或IRR。

执行三组闭合：

1. 房源闭合：分楼栋/户型合计等于首开及整盘汇总。
2. 客储闭合：等级、户型、楼栋和未转筹统计可回到去重客户底表。
3. 经营闭合：价格、面积、货值、去化和合约额一致，财务指标可回到财务确认版本。

### 8. 编排25页报告

严格按 `references/slide-structure.md` 组织。每页先写一句结论，再放支持表图；无数据时保留页码和缺口标记，不用虚构图表填满页面。第24页只保留需要会议批准、知悉或支持的事项，并与正文完全一致。

### 9. 审查和出件

运行 `references/quality-gates.md`。有阻塞项时输出“报告草案 + 阻塞清单”，不标注“可上会”；全部通过后输出“可上会版 + 复算附件 + 数据版本清单”。

## 输出规则

- 先给推荐价格、首开货量、销售目标、整盘影响、风险和决策事项，再展示分析过程。
- 分开呈现住宅、商业、车位，以及毛坯、精装等不同业态。
- 价格统一说明是表价、申请价、底价还是预计实现价；金额统一标明元、万元或亿元。
- ABCD等级不自行增加数值概率；B/C加减级只表达类内相对强弱。
- 客户、竞品、价格、财务和政策数据没有来源时标为缺失，不做伪精确推断。
- “全计息”和“全投资”均按“全投资计息”的简称处理，不拆成两套模型。财务提供值优先；未提供专门公式时按指标字面含义表述并标记 `待财务复核`，不另造企业公式。
- 对开发票面文案、图片或地图的事实与合规终审调用 `content-compliance`。

## 交付模式

- `完整报告`：25页逐页文案、表格字段、图表说明和附件清单。
- `决策摘要`：首开时间、方式、范围、价格、目标、车位、整盘影响及支持事项。
- `数据底稿`：输入台账、复算结果、版本差异和待确认项。
- `报告审查`：逐页问题、严重程度、修改建议和是否可上会。
- `报告骨架`：输入不足时提供固定结构和资料责任清单，不虚构结论。
