# 销售话术教练项目内部竞赛介绍

## 一句话介绍

`sales-talk-coach` 是一个面向房地产新房案场的 AI 销售训练工具。它不是简单生成话术，而是围绕“项目说辞考核”和“客户接待对练”两个真实管理场景，帮助销售练讲盘、练接待、练谈价、练逼定，并在训练后给出评分、问题清单和优秀示范。

## 项目要解决的问题

一线案场培训长期有四个痛点：

1. 新人培训依赖师傅带教，标准不统一，学得快慢取决于带教水平。
2. 销售会背项目，不代表能应对客户异议、价格谈判和临门一脚。
3. 管理者复盘主要靠经验判断，缺少稳定的评分维度和可沉淀的话术样本。
4. 合规风险难以在日常演练中持续提醒，销售容易说出学区、升值、底价、特批等高风险表达。

这个项目的价值，是把销售培训从“口头传经验”变成“可演练、可评分、可复盘、可复制”的日常训练工具。

## 应用场景

- 新人入职：先练项目基础说辞，再进入模拟客户接待。
- 晨夕会训练：每天抽 10 到 15 分钟，围绕一个异议或一个客户阶段做对练。
- 开盘前演练：统一项目价值点、价格口径、竞品对比和逼定边界。
- 老销售复盘：把实际接待中流失的客户场景还原出来，重新演练更优路径。
- 管理者带教：用统一评分表看出团队短板，而不是只凭感觉评价。

## 项目意义

### 1. 降低训练成本

过去销售训练需要管理者、销冠或老员工反复扮演客户，时间成本高，而且水平不稳定。AI 可以随时生成客户场景，让销售高频、低成本地练习。

### 2. 统一考核标准

传统评价容易依赖个人经验。项目把说辞考核、客户对练、评分维度和合规边界写成统一规则，让不同销售接受相对一致的训练和评价。

### 3. 提升实战转化能力

系统不只检查销售会不会背项目，还训练销售能不能问出需求、拆清资金、识别决策人、处理竞品、推动现场定房，更贴近案场真实转化。

### 4. 支持多项目复制

通过考核规则和项目资料分离，同一套训练方法可以迁移到不同项目。换项目时重点更新项目资料，而不是重新搭建整套工具。

### 5. 沉淀组织能力

训练结果、优秀示范和常见问题可以沉淀为团队话术资产，帮助组织把个人经验转化为可复用的培训能力。

## 创新点

### 1. 模式创新：AI 驱动的千人千面考核训练

核心创新是利用 AI 的开放对话、角色扮演和动态反馈能力，替代传统人工基于经验的考核。过去考核依赖管理者现场提问和主观判断，现在可以由 AI 生成不同客户、不同阶段、不同难度的训练场景。

销售面对的不是固定题目，而是千人千面的客户：有人压价，有人犹豫，有人带家人，有人看竞品。AI 会根据销售回答继续追问和反馈，但底层评分标准保持统一，从而实现“客户千人千面，标准基本统一”。

### 2. 形式创新：轻量化 Skill，低门槛多端部署

项目采用 skill 这种轻量化形式，不需要重系统开发，也不需要复杂部署。内容主要通过 Markdown 和规则文件组织，业务人员可以直接编辑、补充和迭代。

这种形式的好处是灵活、门槛低、用途广。无论是在 Codex、Claude 这样的个人 AI 工具里，还是在 OpenClaw、Hermes 这类 Agent 平台中，都可以快速部署、修改和迁移。人人都可编辑，处处都能调整。

### 3. 架构创新：考评体系与项目资料解耦

项目架构上把“考核评价规则”和“项目资料”拆开。考核评价规则在项目之间共享，负责统一训练流程、评分维度、客户阶段和合规边界；项目资料库则按项目独立配置，负责项目卖点、价格口径、竞品资料和客户分层。

这种设计让软件能力和项目资料各自迭代：软件方面可以持续升级训练方式、评分规则和复盘报告；资料方面可以由各项目团队自行更新。换项目时主要改项目资料，就能实现技术迁移，具备复制性。

### 4. 导向创新：从说辞掌握到客户转化能力

项目既有项目说辞考核，也有客户接待对练。前者关注销售是否掌握标准化项目说辞，后者关注销售是否能在真实客户沟通中推动转化。

它不仅检查“讲得对不对”，还检查“能不能成交”：是否问出真实需求、是否拆清资金压力、是否识别决策链、是否处理竞品异议、是否推动客户现场决策。再加上评分评估和优秀案例示范，使训练更实战、更实用。

## 当前成果

目前项目已经形成了一个可演示、可训练、可继续扩展的基础版本。它不是一个单纯的话术文档，而是一个“技能入口 + 规则体系 + 项目资料”的训练原型。

```text
+-------------------------------------------------------------+
| sales-talk-coach                                             |
| AI 销售训练 Skill                                            |
+-------------------------------------------------------------+
                              |
              +---------------+----------------+
              |                                |
+-------------v-------------+    +-------------v----------------+
| SKILL.md                   |    | references                   |
| 技能入口与流程调度层        |    | 训练资源与项目资料层          |
+---------------------------+    +------------------------------+
| 1. 识别训练类型            |    | 规则类                        |
|    - 项目说辞考核          |    | - 客户模型生成规则             |
|    - 客户接待对练          |    | - 谈价与逼定规则               |
|                            |    | - 评分标准与复盘模板           |
| 2. 控制训练过程            |    | - 项目说辞考核规则             |
|    - 难度                  |    |                               |
|    - 阶段                  |    | 资料类                        |
|    - 状态机                |    | - 项目基础资料                 |
|                            |    | - 优秀销售案例                 |
| 3. 管理训练边界            |    | - 训练样例                     |
|    - 价格                  |    | - 项目配置模板                 |
|    - 学区                  |    |                               |
|    - 竞品                  |    |                               |
|    - 逼定合规              |    |                               |
+---------------------------+    +------------------------------+
```

现阶段可以概括为六项成果：

1. 入口清晰：已经区分项目说辞考核和客户接待对练两类核心场景。
2. 流程完整：已经覆盖首访、复访谈价、逼定成交三个阶段，并区分初级、中级、高级难度。
3. 规则可复用：客户模型、谈价逼定、评分标准、反馈报告和项目考核规则已经独立成文。
4. 资料有样板：默认项目、优秀示范、训练样例和项目配置模板已经具备基础样板。
5. 复盘有闭环：训练后可以输出评分、扣分原因、问题清单和优秀销售示范片段。
6. 合规有边界：已修正主动引导争取额外优惠、主动放客户改天再来、流程表达过度书面化等问题，更贴近真实案场要求。

## 当前不足与未来规划

不足和展望应该放在一起看，因为每一个不足都对应下一阶段的建设方向。

### 1. 内容扩展：从单一项目到多类型训练库

当前版本主要围绕一个常规改善型项目展开，适合验证训练流程和评价框架。但真实业务中，刚需、改善、豪宅、投资、自住兼投资等项目类型差异很大，客户关注点、价格敏感度、价值转化方式和成交推动节奏都不一样。

下一步可以按项目类型建立训练库，把“项目说辞”和“成交打法”一起沉淀。刚需项目重点训练总价门槛、通勤效率、首付月供分解和上车决策；改善项目重点训练家庭场景、空间升级、长期居住价值和现场决策推动；豪宅项目重点训练信任建立、节奏把握、圈层价值、资产配置和高净值客户沟通；投资类项目重点训练板块逻辑、出租流通性、机会成本和风险边界。

### 2. 底座升级：从文档型 Skill 到统一技能层 + 项目数据库

当前版本已经做了初步分层：`SKILL.md` 和规则类文件承担统一训练能力，项目资料和案例放在 references 中。但这还停留在 Markdown 文档组织阶段，适合快速验证，不适合长期规模化管理。

下一步应该建立统一技能层和项目数据库。统一技能层负责流程调度、客户模拟、评分标准、复盘模板和合规边界，可以统一版本控制、统一升级迭代；项目数据库负责各项目自己的卖点、价格、竞品、客户分层和成交口径，各项目只维护自己的数据。这样既能保证考评体系统一，又能让不同项目低成本复制和独立更新。

### 3. 管理贯通：从训练结果到销售人才数字化档案

当前版本主要服务训练和复盘，数据还停留在单次训练结果层面。未来如果接入人力系统，这些记录就不只是业务训练数据，也可以成为销售人才数字化档案的一部分。

招聘环节可以通过模拟接待评估候选人的表达、逻辑、抗压和转化潜力；新人培养可以记录从入职学习到独立接待的成长路径；岗位考评可以结合训练成绩、短板分布和进步速度，形成个人能力画像和团队能力地图。这样项目就不只是培训工具，也能服务招聘、培养、考评、晋升和培训管理。

### 4. 能力跃迁：从销售训练 Agent 到 AI 销售能力体

当前项目的定位是训练人，核心价值在于帮助销售更好地掌握说辞、处理异议、推动成交。远期看，当系统积累足够多的客户模型、成交场景、优秀话术、项目资料和转化数据后，它有机会从“训练销售”进一步走向“辅助销售”。

短期可以辅助销售做客户分析、话术建议、异议拆解和复盘提醒；中期可以在直播、企微、线上咨询、私域跟进中承担初步接待和持续沟通；长期在标准口径明确、合规边界清晰、客户问题可结构化处理的场景中，可以探索 AI 与人类案场共销、网络销售和 AI 员工雏形。

## 向评委介绍时的建议表达

可以这样开场：

> 这个项目不是为了替销售说话，而是为了让销售每天都能低成本、高频次地练习真实客户接待。它把项目讲解、客户画像、异议处理、逼定动作和合规边界放进同一套训练流程里，帮助案场把经验型带教变成标准化训练。

演示时建议选择一个“高级逼定成交”场景，让评委看到：

1. 系统先给销售公开可观察信息和案场已掌握信息。
2. 销售开始接待，AI 扮演客户提出价格、家人、竞品等阻力。
3. 结束后系统给出评分、问题清单和优秀示范。
4. 示范中体现现场解决问题、现场定房、合规表达和不虚构承诺。

这样评委更容易理解它的应用价值，而不是把它看成普通话术生成器。
