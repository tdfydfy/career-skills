# 价值扫描与排序框架

## 一、五维扫描

| 维度 | 关注内容 | 常见证据 | 典型客户任务 |
|------|----------|----------|--------------|
| 城市与区位 | 城市角色、板块能级、交通、产业、公共资源、发展阶段 | 规划批复、公开数据、实测通勤、政府公示 | 通勤效率、资产安全、长期判断 |
| 土地与自然 | 江河湖山、公园、朝向、视野、地形、稀缺界面 | 红线图、现场踏勘、测绘、照片、视线分析 | 景观享受、稀缺性、松弛感 |
| 规划与产品 | 容积率、楼间距、楼栋排布、户型、立面、精装、收纳、设备 | 设计图纸、户型图、样板间、交付标准、实测 | 好不好住、是否值得溢价、家庭适配 |
| 生活与服务 | 会所、园林、物业、归家、社群、儿童/老人场景、交付兑现 | 服务标准、运营方案、现场体验、业主反馈 | 省心、体面、家庭关系 |
| 情绪与身份 | 归属、犒赏、进阶、圈层、传承、安心、错过成本 | 客户访谈、成交复盘、内容测试、品牌资产 | 为什么现在买、买给谁看 |

## 二、证据等级

- **A 已证实**：合同、批复、已交付标准、实测结果、现场可验证事实。
- **B 高可信**：正式设计方案、供应商/物业标准、已公开且可追溯的规划信息；需注明兑现节点。
- **C 待验证**：口头信息、意向方案、预测数据、客户单点反馈、尚未确认的竞品信息。
- **D 创意假设**：用于测试表达或体验的建议，不得写成项目承诺。

价值点卡片建议使用以下字段：

```text
价值点：
所属维度：
客户任务：
事实与证据：
证据等级：A/B/C/D
独特性：与哪些竞品相比不同
可感知方式：看见 / 走过 / 使用 / 被服务 / 被证明
适配客群：
当前阶段：
风险与待核实：
```

## 三、优先级评分

在信息允许时用 1~5 分粗评，不要制造虚假的精确度：

`优先级 = 客户重要性 × 项目独特性 × 证据强度 × 可感知性`

评分解释：

- 客户重要性：不满足是否会直接放弃或显著降低意愿。
- 项目独特性：竞品是否容易复制，是否具有时间/空间/资源壁垒。
- 证据强度：A=5、B=4、C=2、D=1；用户可按实际调整。
- 可感知性：客户能否在一次到访或一段内容中理解并验证。

评分只用于取舍。分数高但证据不足的点，进入“重点补证”，不能直接进入承诺型传播。

## 四、价值层级

1. **总核心价值**：客户选择该项目的总理由，只保留一个。
2. **一级价值**：支撑总核心价值的 3~5 个价值簇，通常覆盖区位、产品、生活、信任或情绪中的关键组合。
3. **证明点**：可以被资料、现场、体验或第三方口碑验证的具体事实。
4. **表达点**：将证明点翻译成销售话术、视觉、标题或体验命名；表达点不能反过来替代证明点。
