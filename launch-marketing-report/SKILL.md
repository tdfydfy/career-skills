# 项目首开型营销策略报告

## 定位

形成一份从“为什么这样做”到“做什么、做到多少、花多少钱、何时调整”完整闭合的项目营销策略报告。把首开价格报告视为价格与量价目标的专项成果，不在本报告中用价格表代替策略推导。

本技能处理全新项目入市、首开或需要完整重建首开策略的关键批次。项目进入常态持销且没有重新定位或大型加推任务时，路由到持销报告或项目诊断。

## 必读资料

开始时读取：

- `references/strategy-logic-chain.md`：先建立策略暗线和推导记录。
- `references/input-checklist.md`：判断事实、策略和执行输入完整度。
- `references/decision-framework.md`：选择经营策略和推售模式。
- `references/report-template.md`：组织前置摘要及五部分报告。
- `references/quality-gates.md`：检查逻辑、指标、预算、执行和合规闭合。

在网络仓库内读取 `../framework/foundations/decision-reasoning-standard.md` 和公共契约。按需调用市场、客储、价格货量、营销策略、获客、媒体、渠道、活动、推广、展示、销售、费用和跨专业协同节点。调用 `storyline-creation` 形成故事线，调用 `content-compliance` 审查对外口径。

## 入口确认

确认：

1. 报告是新编、更新还是审查，服务项目、地区还是总部决策。
2. 当前处于定位、入市、展示、蓄客、认筹还是首开阶段。
3. 公司对项目优先规模、利润、现金流、标杆还是库存，以及不能突破的指标。
4. 报告需要决定哪些范围、节点、目标、资源、费用和权限。

## 完整度处理

- `A`级：公司任务、项目、市场、客户、货量、展示、价格、渠道历史、预算和节点资料齐全，输出完整策略报告。
- `B`级：核心事实具备，但客户、渠道效率、预算或展示有缺口，输出条件性策略、验证动作和情景目标。
- `C`级：只有项目介绍和方向性要求，输出事实缺口、策略推导骨架和调研计划，不生成伪精确渠道占比、转化率或费用。

## 工作流

### 1. 明确经营命题

先写公司意图、项目任务、成功标准、约束和待决策事项。把启动会、年度指标、利润现金流和品牌任务作为经营起点，不让市场章节自行决定项目目标。

### 2. 建立事实底盘

建立项目、市场、客户、货量、展示、价格、组织、费用和财务上下文。所有数字记录范围、单位、日期、来源、版本和状态；分开事实、观察、推断、预测和承诺。

### 3. 建立策略推导链

按 `references/strategy-logic-chain.md` 形成推导表：

`公司意图 → 项目条件 → 市场竞争 → 客户需求/承价 → 核心矛盾 → 策略命题 → 选择与取舍 → 动作 → 漏斗目标 → 预算 → 复盘`。

先完成推导表，再写PPT。任何无法回到证据和公司意图的主张，不进入核心策略。

### 4. 形成三类判断

1. 市场与竞争：容量、库存、价格带、未来供应、竞品动作和首开窗口。
2. 客户与产品：目标客户、痛点、购买动机、预算、承价、产品匹配、抗性和客储成熟度。
3. 项目与经营：货量、批次、展示、工程、价格、费用、团队和跨专业约束。

把三类判断交叉，最多保留三个核心矛盾和三个结构性机会。

### 5. 确定策略命题

写明争取谁、依靠什么价值和资源、解决什么矛盾、实现什么指标、放弃什么。比较基准、进取和谨慎路径；选择集中开盘、分批释放或持续推售，并说明条件。

### 6. 设计价值与动作体系

从客户痛点和竞品缺口选择土地、配套、产品、品牌、展示和服务证据，形成价值主张。再按入市、强蓄、认筹、升筹、开盘阶段编排推广、内容、活动、展示、渠道、销售和协同动作。

不得先选择活动创意再倒推策略。模板中的机器人、花车、私宴、积分制等只作为备选案例，必须验证客户匹配、预算、效果、权限和合规。

从开盘阶段同步设置住宅与车位量价和车住销售比目标。可在住宅房号底价之上设计客户自愿的房车组合权益，并将车位纳入人员考核；不得强制捆绑或突破住宅、车位和费用权限。

### 7. 反推目标与预算

从销售套数、金额和回款目标反推认筹、有效客户、来访和线索，按渠道分解成交、认筹、来访、动作量和费用。说明每层转化率和渠道占比的来源，校验分项合计。

项目历史数据优先；缺少可靠历史数据时，持销来访成交可暂按约10%，首开来访认筹约15%、认筹成交约60%作为经验测算起点。标记为假设并设置替换时间，不把经验值当作项目承诺。

费用分解到阶段、科目和重点动作，同时给出营销费率、单位有效客户成本、单位成交成本、调整和退出规则。整盘可暂按约2.5%控制，首开阶段可适度至约3%，但必须同步铺排后续压降路径。

### 8. 形成五部分报告

使用“管理摘要 + 项目基本情况 + 市场竞品情况 + 价值策划及推广策略 + 客储策略 + 费用预算”的结构。每部分都服务于策略命题，不把分析、动作和预算写成互不关联的章节。

### 9. 执行质量门槛

运行 `references/quality-gates.md`。逻辑链断裂、目标无法反推、重点动作没有经营作用或费用无法对应目标时，不标记为“可执行”。

## 输出纪律

- 先呈现公司任务、核心矛盾、策略命题、量价目标和决策事项，再展开证据。
- 每个分析结论补一句“所以对本项目意味着什么”。
- 每个动作写明解决的问题、目标客户、目标房源、节点、预算、指标和调整规则。
- 明确不做事项和被否决方案，避免资源平均分配。
- 不编造市场、客户、价格、转化、渠道占比、效果、费用或政府和业主背书。
- 客户名单、电话、身份证、单位信息、推荐奖励、教育规划和投资表达必须通过隐私、法务、财务和权限审查。
- 对外内容只输出经事实校验的任务书，发布前调用 `content-compliance`。

## 交付模式

- `完整报告`：管理摘要、五部分正文、推导表和附件。
- `策略摘要`：经营命题、核心矛盾、策略选择、目标、预算、风险和决策事项。
- `报告骨架`：信息不足时输出推导问题、目录、数据责任人和验证计划。
- `报告审查`：逐条检查证据→判断→策略→动作→目标→预算链条，并给出断点和修改建议。
