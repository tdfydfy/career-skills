# 事实、假设与证据管理标准

状态：`draft`

## 目的

保证营销判断、策略和成果中的关键结论可追溯，避免把经验、预测、未经确认的信息写成事实。

## 信息类型

| 类型 | 定义 | 使用要求 |
| --- | --- | --- |
| `fact` | 已发生且有可靠来源支持的信息 | 记录来源、日期、范围和状态 |
| `metric` | 按已登记公式计算的数据 | 记录指标ID、公式版本和统计周期 |
| `assumption` | 为推进分析暂时采用的前提 | 说明理由、影响和验证动作 |
| `observation` | 基于有限样本形成的现象描述 | 不直接外推总体结论 |
| `inference` | 从事实和指标推导的业务判断 | 明确推理链和置信度 |
| `forecast` | 对未来结果的情景预测 | 说明基准、乐观、谨慎情景及变量 |
| `commitment` | 经授权可对内或对外确认的承诺 | 记录授权人、依据、范围和有效期 |

## 证据等级

- `A`：正式系统、合同、批复、财务确认、政府或公司正式文件。
- `B`：经责任人确认的业务台账、会议纪要、调研原始数据。
- `C`：销售反馈、客户访谈、竞品踩盘和渠道反馈等一线信息。
- `D`：经验判断、传闻、单一样本或尚未核实的信息。

重大价格、费用、利润、开盘和对外承诺不得只依赖C或D级证据。C级信息可以形成假设，但必须安排验证。

## 新鲜度

默认建议周期如下，企业制度优先：

- 项目销控、价格、来访、成交和客储：每日更新。
- 竞品价格、政策、货量和渠道动作：至少每周核验，重大节点即时更新。
- 城市市场成交和供应：按官方或主要数据源发布周期更新。
- 费用、签约、回款和财务边界：按财务结账或专项决策时点更新。
- 政策、规划、学校和交通：引用时核验当前有效文件。

超过建议周期的信息标记 `stale`，可用于历史分析，不得无提示用于当前决策。

## 冲突处理

1. 先检查统计范围、时间和状态是否一致。
2. 正式系统和批复优先于手工汇总，但系统异常必须保留核对记录。
3. 项目专属事实优先于通用案例和默认模板。
4. 财务、法务、工程等专业事实由对应责任部门确认。
5. 无法裁决时并列呈现冲突值，不取平均，不隐藏差异。

## 预测规则

- 至少建立基准情景；高风险决策增加谨慎和乐观情景。
- 区分可控变量和外部变量。
- 不使用单点预测伪装确定性。
- 预测结果必须注明数据截止时间和失效条件。
- 实际结果产生后回写偏差和原因，用于修正后续假设。

## 销售质量风险证据

- 签约周期超过7天、超过14天或认购/签约退房率超过5%时，先标记风险并核查客户底表、付款条件、按揭进度、销售跟进和审批记录。
- 异常比例可以触发“可能存在客户违约、销售质量或虚假销售风险”的判断，但不能在缺少客户及审批证据时直接认定虚假销售。
- 特殊原因造成签约延迟时，逐单记录原因、责任人、预计签约日和验证状态，不用笼统说明覆盖长期异常。
- 认购退房和签约退房分别保留发生日期、原交易日期、审批层级、原因和金额，不追溯覆盖历史事实。

## 对外信息规则

- 规划、学校、交通、价格、优惠、房源、交付和服务必须使用已授权口径。
- 未确认信息不得通过“据说”“内部消息”等方式变相发布。
- 效果图、示意图、样板间和非交付标准必须显著标注。
- 对外材料同时遵守 `content-compliance` 和企业品牌标准。

## 标准记录

使用 `../contracts/fact-record.yaml`。关键结论至少关联一个证据记录；没有证据时只能标记为假设或数据缺口。

## 待企业校准

- 正式数据源清单及系统优先级。
- 各数据类型的责任部门、更新周期和审批人。
- A至D级证据在不同决策中的最低要求。
- 会议口头确认转为正式依据的流程。
- 对外承诺的授权清单和有效期管理。
