# 营销成果策略推导标准

状态：`draft`

## 目的

让报告中的结论、目标和动作由同一条经营逻辑推导，而不是把市场、客户、推广、客储和预算章节并列拼接。所有成果都应保留可审查的逻辑暗线，项目营销策略报告需要把这条暗线显性呈现。

## 标准推导链

```text
公司经营意图与约束
  → 项目、产品、货量、展示和工程条件
  → 市场容量、竞争关系和窗口
  → 客户需求、承价、客储和抗性
  → 核心矛盾与机会
  → 策略命题及取舍
  → 价格、推售、价值和客户选择
  → 推广、展示、获客、销售和协同动作
  → 来访、认筹、成交、回款和费用目标
  → 监测、调整和复盘
```

## 六个逻辑接口

### 1. 公司意图到项目任务

默认从“销售业绩主导、兼顾利润”出发，读取集团、地区已正式下达的项目任务、利润约束和专项要求，并写明不能突破的指标、权限和节点。未被正式提供的公司整体业绩、宏观判断和跨项目取舍不得由项目分析自行推断。

项目策略分析应调动市场、客户、销售、货量、价格、财务和专项任务等模块，建立项目客观事实和情景测算。成果可以给出项目层面的策略倾向、适用条件和风险，但最终决策事项应提交集团、地区结合整体业绩、宏观市场和资源配置判断。

### 2. 市场客户到核心矛盾

市场回答容量、价格带、竞争和窗口；客户回答购买动机、产品选择、承价、抗性和成交条件。将两类证据与项目条件交叉，只保留一至三个真正影响目标的矛盾，不用“市场竞争激烈”等空泛判断代替。

用户、管理者或一线人员可以提出、补充和修正主因。非纸面因素按专业判断单独记录判断人、角色、观察场景、理由和置信度，与数据结论交叉校验；不因缺少书面材料直接排除，也不把匿名意见或无理由结论伪装成事实。

### 3. 核心矛盾到策略命题

策略命题同时写明：争取谁、用什么价值或资源、解决什么矛盾、实现什么目标、放弃什么。每个命题至少比较一个备选方案，并说明选择和不选择的原因。

项目诊断成果采用总—分表达：先综合说明整体经营判断、核心矛盾关系和项目策略倾向，再以每条主因为分支，将项目证据、专业判断、影响对象或漏斗环节、对应策略和适用条件连成一条推导链。不得在诊断后另列一组无法回到主因的通用策略。

### 4. 策略到动作

每项重点动作必须指向某个矛盾或策略命题，并写清目标客户、目标房源、阶段任务、责任人、预算、前置条件、领先指标、结果指标和停止/调整规则。只有创意但没有经营作用的活动不进入主策略。

项目诊断只展开重要节点和关键行动，一般执行细节由项目动作计划管理。超出项目权限的事项在对应主因分支中标记地区支持或集团决策，并在最后小结按项目执行、地区协调、集团决策统一汇总，不把支持请求混作项目自身动作。

### 5. 动作到漏斗与预算

从销售目标反推认筹、有效客户、来访、线索和渠道目标。说明每层转化率的来源，将各渠道目标、动作量和费用与漏斗对应。不得一边给出销售目标，一边使用无法支撑目标的渠道和预算。

### 6. 结果到复盘

为项目市场、客户、价格、动作和费用假设设验证节点，记录失效条件、复盘日期及切换方案。集团、地区的正式管理判断作为输入保留来源和有效期，不由项目结果反向包装为既定事实。实际结果偏离时，区分假设错误、执行不足和外部变化，再调整策略；不只检讨活动是否按时完成。

## 反模式

- 先想活动或传播口号，再倒找市场和客户理由。
- 罗列项目卖点，但不解释客户为什么在当前总价下购买。
- 用单个竞品价格直接推出本案价格，不考虑产品、客户和货量差异。
- 渠道成交占比、来访量和认筹量互相不能反推。
- 所有渠道都做、所有客群都要，没有资源取舍。
- 预算按历史比例分配，与目标和动作贡献无关。
- 把案例动作、行业流行做法或领导偏好写成项目事实。

## 最低质量门槛

- 每个核心结论至少有一个事实、证据或可追溯的专业判断，并说明经营含义。
- 每个主策略能回到核心矛盾、项目任务和已正式提供的管理输入。
- 每条主因都能闭合到项目证据或专业判断、影响环节、对应策略、关键行动和复盘规则。
- 每个重点动作能回到策略、目标客户、房源和漏斗指标。
- 销售、认筹、来访、渠道目标和预算能够相互复算。
- 明确不做事项、失效条件和复盘时间。
