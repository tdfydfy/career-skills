# 营销动作库

状态：`draft`

机器可读动作见 `../knowledge/marketing-action-baseline-001.yaml`。

## 目的

把“做活动、上渠道、调价格”等宽泛建议拆成可选择、可审批、可跟踪和可复盘的动作单元。

## 动作选择

每个动作必须回答：

1. 解决哪个具体瓶颈。
2. 有什么事实和指标支持。
3. 适用于哪些客户、房源、渠道和时间。
4. 需要什么价格、费用、人员和跨专业资源。
5. 用哪些领先指标判断执行，用哪些滞后指标判断结果。
6. 达不到什么条件时停止、调整或升级。

## 动作类别

- `value`：价值体系、展示、实景和信任证据。
- `acquisition`：地推、新媒体、直播、老带新和圈层获客。
- `channel`：分销及合作渠道。
- `conversion`：客户盘点、销售训练、复邀和节点转化。
- `price-inventory`：价格梯度、特价房、分批推售和资源组合。
- `organization`：激励、专项协同和经营复盘。
- `transaction`：签约、按揭和回款推进。

## 组合原则

- 来访不足：优先检查客户范围、触达和承接，再选择获客或渠道动作。
- 来访充足但转化弱：优先检查客户质量、产品匹配、价格、展示和销售执行。
- 结构性库存：先定位具体房源问题，再组合价格、价值、客户和渠道动作。
- 客储充足且节点明确：可评估集中推售；客储弱时不以活动制造虚假热度。
- 价格动作必须与财务、库存和后续价格体系联动。
- 持销异常：先复盘前期得失并验证根因，优先测试团队、价值、展示、传播、获客、渠道、激励和执行等可逆动作。
- 产品和价格通常靠后，但证据证明其为主要根因且经营窗口有限时，应及时升级，不用低效动作拖延。
- 家电、装修、封窗等权益必须解决明确客户抗性、折算成本并明确合同和交付责任。
- 价格和权益动作检查公开价格、后续货量、项目口碑和老业主感受。
- 开盘及持销阶段同步设置住宅和车位目标；房车组合应自愿、透明并在底价及权限范围内。

## 动作计划

使用 `../contracts/marketing-action-plan.yaml`。一个方案可以包含多个动作，但每个动作都必须有独立责任人、预算、期限和复盘指标。

## 动作执行事实

AI通常不能仅凭销售结果知道项目实际执行了哪些动作。项目应在现有周报、月报或专题材料中填报动作执行，也可以由AI从会议纪要、费用记录、渠道媒体后台和系统记录中提取后交项目确认，不另设通用问卷。

每项动作分开记录计划、实际执行和执行后结果：计划说明目标、客户房源、时间、预算和指标；实际执行说明完成状态、实际时间、范围、频次、费用、交付物和偏差；结果说明客户及领先指标、客储变化、销售结果、项目判断和归因置信度。计划不能视为已执行，活动到场或曝光也不能自动视为销售效果。

管理汇报只纳入重要节点和关键行动，例如拓客活动、佣金调整、展示开放、认筹启动、开盘加推、价格调整或重大渠道政策。每项关键行动同步汇报费用、实际效果和客储数据；一般邀约、物料修改、例行培训等日常细节不要求汇报，除非其执行偏差被判断为项目问题的重要原因。

项目负责人和一线人员可以补充非纸面执行情况及现场效果，按专业判断记录来源、场景和理由。没有关键动作执行输入时标记 `unknown`，不得根据销量变化反推动作已经执行、未执行或必然有效。

## 红线

- 不虚构优惠、房源紧张、涨价和领导特批。
- 不把活动到场、曝光和播放量直接等同于有效客户或成交。
- 不用赠送掩盖不可交付或未审批内容。
- 不用渠道带看来替代案场转化问题的诊断。
- 不因短期冲量突破价格、费用、个人信息和广告合规边界。
- 不以房车同售名义实施强制捆绑、价外加价或隐瞒客户选择。

## 待企业校准

- 企业常用动作名称、编码和归口部门。
- 各动作的费用科目、审批权限和采购周期。
- 各城市可用渠道、平台和供应商资源。
- 活动、媒体、渠道的历史基准效率。
- 动作退出标准和复盘归档机制。
